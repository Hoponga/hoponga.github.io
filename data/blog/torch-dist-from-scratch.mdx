There's a particular frustration that comes with using torch.distributed and getting obscure NCCL bugs which either take you down a
rabbit hole of StackOverflow/Github issues, or in the modern day require hours of Claude spinning until you realize some environment variable wasn't set properly and breaking everything, or your rank/world-size calculation was wrong.
Or, you keep wondering why your 8 GPU job is hanging only to realize your lab cluster only connects pairs of GPUs together, so of course an 8-GPU sync would hang! The underlying problem in all these cases is that I've never asked how torch.distributed works under the hood, or even
the inner workings of how NCCL works.

And I'm not about to go through the github of PyTorch to learn this, so I figured I'll try and rewrite torch.distributed from scratch! Or, not from scratch, but rather from NCCL, which honestly already provides methods to implement a lot of the torch.distributed collectives. So mainly this is a project
to understand what is necessary on TOP of NCCL to enable Pytorch-distributed type features.

### High-Level Goal

As a high-level goal we should create a library that's capable of doing the torch.distributed basics. For example, we should be able to do collectives:

```python

def main():
    dist.init_process_group(backend="nccl")
    rank = dist.get_rank()
    world_size = dist.get_world_size()

    tensor = torch.tensor([rank + 1.0]).to("cuda")
    print(f"[rank {rank}] before all_reduce: {tensor.item()}")
    dist.all_reduce(tensor, op=dist.ReduceOp.SUM)
    print(f"[rank {rank} sees tensor {tensor.item()}]")
    dist.destroy_process_group()


if __name__ == "__main__":
    main()
```

as well as p2p communication:

```python
import torch
import minidist as dist


def main():
    dist.init_process_group(backend="nccl")

    rank = dist.get_rank()
    world_size = dist.get_world_size()
    assert world_size == 2

    if rank == 0:
        tensor = torch.tensor([42])
        print(f"[rank 0] sending {tensor.item()} to rank 1")
        dist.send(tensor, dst=1)
    else:
        tensor = torch.zeros(1)
        dist.recv(tensor, src=0)
        print(f"[rank 1] received {tensor.item()} from rank 0")

    dist.destroy_process_group()

    main()
```

## Intro to NCCL

Truth be told, I've never really written NCCL code before and so the first step is getting pretty familiar with the programming model. Lets start with a simple all-reduce script that does the same as the above, taken from the official documentation [1]:

```c++
#include <stdlib.h>
#include <stdio.h>
#include "cuda_runtime.h"
#include "nccl.h"

#define CUDACHECK(cmd) do { \
 cudaError_t err = cmd; \
 if (err != cudaSuccess) { \
 printf("Failed: Cuda error %s:%d '%s'\n", \
 **FILE**,**LINE**,cudaGetErrorString(err)); \
 exit(EXIT_FAILURE); \
 } \
} while(0)

#define NCCLCHECK(cmd) do { \
 ncclResult_t res = cmd; \
 if (res != ncclSuccess) { \
 printf("Failed, NCCL error %s:%d '%s'\n", \
 **FILE**,**LINE**,ncclGetErrorString(res)); \
 exit(EXIT_FAILURE); \
 } \
} while(0)

int main(int argc, char\* argv[])
{
ncclComm_t comms[4];

//managing 4 devices
int nDev = 4;
int size = 32*1024*1024;
int devs[4] = { 0, 1, 2, 3 };

//allocating and initializing device buffers
float** sendbuff = (float**)malloc(nDev _ sizeof(float_));
float** recvbuff = (float**)malloc(nDev _ sizeof(float_));
cudaStream_t* s = (cudaStream_t*)malloc(sizeof(cudaStream_t)\*nDev);

for (int i = 0; i < nDev; ++i) {
CUDACHECK(cudaSetDevice(i));
CUDACHECK(cudaMalloc((void**)sendbuff + i, size \* sizeof(float)));
CUDACHECK(cudaMalloc((void**)recvbuff + i, size _ sizeof(float)));
CUDACHECK(cudaMemset(sendbuff[i], 1, size _ sizeof(float)));
CUDACHECK(cudaMemset(recvbuff[i], 0, size \* sizeof(float)));
CUDACHECK(cudaStreamCreate(s+i));
}

//initializing NCCL
NCCLCHECK(ncclCommInitAll(comms, nDev, devs));

//calling NCCL communication API. Group API is required when using
//multiple devices per thread
NCCLCHECK(ncclGroupStart());
for (int i = 0; i < nDev; ++i)
NCCLCHECK(ncclAllReduce((const void*)sendbuff[i], (void*)recvbuff[i], size, ncclFloat, ncclSum,
comms[i], s[i]));
NCCLCHECK(ncclGroupEnd());

//synchronizing on CUDA streams to wait for completion of NCCL operation
for (int i = 0; i < nDev; ++i) {
CUDACHECK(cudaSetDevice(i));
CUDACHECK(cudaStreamSynchronize(s[i]));
}

//free device buffers
for (int i = 0; i < nDev; ++i) {
CUDACHECK(cudaSetDevice(i));
CUDACHECK(cudaFree(sendbuff[i]));
CUDACHECK(cudaFree(recvbuff[i]));
}

//finalizing NCCL
for(int i = 0; i < nDev; ++i)
ncclCommDestroy(comms[i]);

printf("Success \n");
return 0;
}

````
</details>
There's a couple things to look out for here:
- `cudaSetDevice()` pins each host thread to a specific GPU. NCCL doesn't implicitly know which GPU a thread is talking to — you have to set it yourself before doing anything with that device.
- For each GPU we explicitly allocate send and receive buffers. All_reduce is an in-place operation conceptually, but the C API makes you pass both pointers (you can pass the same pointer for both if you want in-place).
- `ncclCommInitAll` is the easy version — it handles all the communicator setup for you when you have multiple GPUs in the same process. In the real multi-process world (one process per GPU), you'd use `ncclCommInitRank` instead, which requires every rank to pass in the same `ncclUniqueId`. That's actually most of what we need to build on top.

## v0: Building on NCCL

The core problem that torch.distributed solves on top of NCCL is coordination. NCCL itself has no concept of processes finding each other — you have to get every rank to agree on a shared `ncclUniqueId` before any communication can happen. That unique ID is a 128-byte blob that NCCL uses internally to set up the communicator, and every rank needs the exact same one. So the first thing we need is some way for rank 0 to generate the ID and broadcast it to everyone else.

The way torch.distributed does this (and the way minidist does it) is a TCP key-value store. Rank 0 runs a small server, all ranks connect as clients, and rank 0 writes the unique ID under a known key so everyone else can read it. That's it — it's just a way to share a small blob of bytes at startup time. The store is also used for membership tracking (each rank writes a key when it's ready, everyone waits for all keys to exist before moving forward).

The store implementation is pretty simple: a thread-safe dictionary with a condition variable, served over TCP with a text protocol. Commands look like `set mykey aGVsbG8=\n` where the value is base64-encoded. It's not fast but it doesn't need to be — this is control-plane stuff, and you only do it once at startup.

Once coordination is sorted, the actual collective implementation is a pretty thin C++ wrapper around NCCL. The `ProcessGroupNCCL` class holds an `ncclComm_t` communicator and exposes methods for each collective:

```cpp
void ProcessGroupNCCL::all_reduce(torch::Tensor& tensor, ReduceOp op, bool async_op) {
    validate_tensor(tensor, device_);
    cudaStream_t stream = at::cuda::getCurrentCUDAStream(device_).stream();
    std::lock_guard<std::mutex> lock(launch_mutex_);
    NCCLCHECK(ncclAllReduce(
        tensor.data_ptr(), tensor.data_ptr(),
        tensor.numel(),  // element count, not bytes!
        to_nccl_dtype(tensor.scalar_type()),
        to_nccl_op(op),
        comm_, stream));
    if (!async_op) cudaStreamSynchronize(stream);
}
````

A few things worth noting here. First, `tensor.numel()` not `tensor.numel() * sizeof(dtype)` — NCCL takes element counts and handles the size internally based on the dtype you pass. This is a common gotcha. Second, we're using PyTorch's current CUDA stream rather than creating our own, which means the collective gets scheduled in the same stream as whatever kernels came before it. Third, the mutex is there to serialize collective launches from multiple Python threads, though in practice v0 is single-threaded anyway.

The Python layer is just pybind11 bindings over the C++ class, plus some global state to track the default process group:

```python
def init_process_group(backend, rank, world_size, local_rank, ...):
    # rank 0 starts the store server
    if rank == 0:
        _store_server = TCPStoreServer(host="0.0.0.0", port=master_port)
        _store_server.start()

    # everyone connects as a client
    _store = TCPStoreClient(host=master_addr, port=master_port)

    # signal readiness and wait for everyone
    _store.set(f"{run_id}/members/{rank}", b"1")
    _store.wait([f"{run_id}/members/{r}" for r in range(world_size)])

    # rank 0 generates the nccl unique id and shares it
    if rank == 0:
        nccl_id = _C.get_nccl_unique_id()
        _store.set(f"{run_id}/groups/world/nccl_id", nccl_id)
    nccl_id = _store.get(f"{run_id}/groups/world/nccl_id")

    # initialize the communicator
    _default_group = _C.ProcessGroupNCCL(nccl_id, rank, rank, list(range(world_size)), local_rank)
```

One thing that tripped me up initially: we release the GIL during `ncclCommInitRank` (via pybind11's `py::call_guard<py::gil_scoped_release>()`). This matters because on rank 0, the TCPStore server is running in a background thread — and if the main thread holds the GIL while blocking on `ncclCommInitRank`, the server thread can't run, so the other ranks' store reads would hang. Took me a second to figure out why rank 0 was hanging during init.

The launcher is just `subprocess.Popen` in a loop, setting the right environment variables for each rank (`RANK`, `WORLD_SIZE`, `LOCAL_RANK`, `MASTER_ADDR`, `MASTER_PORT`). Nothing fancy — if any process exits non-zero, it kills the rest and propagates the error code.

So putting it all together, a working all_reduce looks like:

```python
import torch
import minidist as dist

def main():
    dist.init_process_group(backend="nccl")
    rank = dist.get_rank()
    tensor = torch.tensor([rank + 1.0]).cuda()
    print(f"[rank {rank}] before: {tensor.item()}")
    dist.all_reduce(tensor, op=dist.ReduceOp.SUM)
    print(f"[rank {rank}] after: {tensor.item()}")  # all ranks see the sum

if __name__ == "__main__":
    main()
```

Run it with `python -m minidist.run --nproc-per-node 4 example.py` and it works. The sum across all ranks shows up correctly on every GPU.
